# Amendments to the frozen evaluation protocol

`EVALUATION_PROTOCOL.md` was frozen on 2026-11-23 (D-097) and is not edited afterwards. Each change is recorded here with its date, reason and decision ID. Results produced before and after an amendment are reported separately.

| Date | Decision | Change | Reason |
|---|---|---|---|
| 2026-11-23 | D-098 | **A1: one common case set for all five models.** The three local models run S0, S1 and S2 on the D-087 hosted-sample lists (300 / 49 / 52 cases), the same cases as the two hosted models. Plan `heldout_plan_A1.json` (9 local jobs, IDs ending `__A1`; record `PROTOCOL_FREEZE_A1.json`). The hosted jobs are unchanged. The full local test lists (1730 / 141 / 156) stay in `heldout_plan.json` and are deferred: if run later they are a separate, secondary analysis. | Owner's request to finish the test runs early. The full local S0 jobs would take about 2 more days of GPU time. The sample was drawn before any test generation by a fixed rule (D-087), and the choice depends only on time cost. Before this amendment only generation status counts had been seen; no test output was read and nothing was scored. All five models are now compared on identical cases. Cost: wider intervals for the local models (about ±12 points per family instead of about ±5). |
| 2026-11-23 | D-099 | **A2: the hosted models are deferred.** The current held-out evaluation covers the three local models only (`heldout_plan_A1.json`). The six hosted jobs in `heldout_plan.json` were stopped at 09:53 UTC (gpt-oss-20b S0 124 of 600 pairs, qwen3.8-27b S0 143 of 600; S1 and S2 not started). Their generations are kept and are not scored now. If they are run later, they form a separate analysis. | Owner's decision not to use hosted models for now, so the test runs finish early (the hosted jobs were limited to 150 calls per day, which meant finishing about 2026-11-28). It was made before any scoring, and only status counts had been seen. Cost: the paper's comparison with larger hosted models is postponed. |
| 2026-11-23 | D-101 | **A3: scoring is no longer gated on Task C.** Plan `heldout_plan_A3.json` is plan A1 with `score_gate` set to none (record `PROTOCOL_FREEZE_A3.json`). The primary test results use `scorer/0.2`, which was fixed before any test generation. Task C (the claim-matcher audit on development claims) becomes a post-hoc validation. If it shows a matcher defect, the fix is made from development items only, gets a new scorer version and re-scores the cached answers. That re-scored result is reported next to the primary one as a sensitivity analysis and never replaces it. | The owner asked to finish as soon as possible and delegated the decision. Annotation would otherwise hold back every result. Keeping the scorer fixed and reporting any later fix only as a sensitivity analysis keeps the primary result free of choices made after seeing test outputs. Cost: a defect that Task C would have found before scoring is found after it, and it is disclosed. |

The Task C result, when the owner completes it, will be the next entry.
